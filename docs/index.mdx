Rundesk keeps the coding CLI you already use — **Codex**, **Claude Code**, **Grok**, **Google
Antigravity** — running as a named teammate with a home of its own. It does not replace them.
It gives them a dependable place to live and a common operating layer.

## Quick start

Run the install command above, then three more to a working teammate.

<Steps>

1. **Create an agent** and check its provider can actually run.

   ```sh
   rundesk add ava --provider codex
   rundesk doctor ava
   ```

2. **Talk to it.** The answer streams back, and the next `ask` resumes the conversation.

   ```sh
   rundesk ask ava "review this repository and tell me the highest-risk open issue"
   ```

3. **Keep it available** after the terminal closes. `launchd` owns the gateway from here.

   ```sh
   rundesk start ava
   ```

</Steps>

[The full walkthrough is in Start here →](/start/first-agent/)

## What Rundesk adds

Coding agents are excellent at a turn of work, but their native home is one terminal session
that ends when you close it. Rundesk adds the parts needed to operate them over time.

<CardGrid>
	<Card title="One identity, one home">
		Every agent has its own workspace, rules, memory, skills, and history, and keeps them
		across turns, surfaces, and restarts.
	</Card>
	<Card title="Always available">
		macOS `launchd` owns each agent's gateway and brings it back after a crash, reboot, or
		automatic update. One gateway per agent, managed independently.
	</Card>
	<Card title="Terminal, chat, and cron">
		Continue the same conversation from the command line, from Discord, or from a
		schedule. It is the same agent either way.
	</Card>
	<Card title="Bring your own brain">
		Four provider CLIs ship first-class. Rundesk uses the login already on your machine and
		never copies provider credentials.
	</Card>
	<Card title="A durable account of every turn">
		Messages, tool activity, outcomes, errors, and token usage recorded per turn, in
		Rundesk's own form rather than a provider's private session format.
	</Card>
	<Card title="Local and recoverable">
		Program and data live in separate directories. Manual and daily backups, explicit
		restore, and no hosted server required.
	</Card>
</CardGrid>
